## Current state

LevelUpDiag-MediKristal is operational as both a CLI validation suite and a Windows Tkinter UI (`LevelUpDiag-MediKristal.pyw`). The UI preloads the MediKristal repository path above, while still allowing another repository directory or ZIP archive to be selected.

The suite contains the original LevelUpDiag diagnostic layers plus MediKristal-specific validation levels. Campaigns available are `baseline`, `software`, `delivery`, `release`, and `deep`.

## MediKristal validation profile

MediKristal-specific levels currently cover:

- `MK10` — repository identity and expected layout
- `MK20` — OpenAPI/contracts/traceability
- `MK30` — FastAPI runtime smoke validation
- `MK40` — Alembic migration validation
- `MK50` — packaging, wheel, SBOM and manifest checks
- `MK60` — reproducibility of generated delivery artifacts
- `MK70` — verification of documented validation claims
- `MK80` — deployment/static production-hygiene checks

## Known limitations

- Docker/PostgreSQL live deployment checks require a machine with those services available.
- Git-related context can report WARN when validating an extracted archive that no longer contains `.git` metadata.
- External MediKristal partner/FHIR capabilities cannot be proven by LevelUpDiag unless the target repository provides the corresponding profiles, credentials, fixtures or test endpoints.
- Reproducibility checks intentionally fail when documented evidence cannot be regenerated from the current repository state.
